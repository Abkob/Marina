Groq delivered 2/7 turns; Nemotron delivered 6/7, including the greeting. The Groq C01, C02 and C14 HTTP 200 responses had `finish_reason: stop`, no native calls and zero public content. They are incomplete model responses, not factual answers. Early receipts label the adapter's error status 502 as `provider_status`; the attempt ledger records the actual provider HTTP 200. Later harness receipts separate actual provider status and adapter/application error status.

The local preflight completed in 296 ms, with actual account headers of 1,000 requests/day and 8,000 tokens/minute. That simple call does not establish complete-answer speed. [Groq's free-limit documentation](https://console.groq.com/docs/rate-limits) also lists 200,000 tokens/day for this model. Successful Groq generation can be fast while repeated growing prompts exhaust the minute allowance. A model context window and an account's throughput allowance are separate limits.

The HTTP 400 cause was not retained in this cohort; do not attribute it to context length, JSON schema, or tool parsing without further evidence.

Existing strict reviewer schemas remained in use. This is a combined protocol/output-budget experiment, not an isolated causal test of JSON mode. Cohort `3335873f-1315-42c3-a8b3-6ec65d74e8f1`, source `4e0cb45413533860cf1b142daf042a4ca60b22172e2613a77bb66c7466df663c`, completed all six attempts. Request-body error causes were not retained and are not inferred from HTTP status alone.

The compact-evidence experiment `78749dc7-9846-4ccd-beec-e2c25e4cd6fa` (source `158ecc13d93eb11a8e9ba6ac0e0bd87f1e8d9c5547c9c3de608ed3d4ae37c292`) supplied identical independent arithmetic facts in a single strict-JSON call per model, with no tools or reviewer loop. Both delivered 2/2, but **all four answers failed independent correctness/usefulness**. Both invented parent purpose or completion for C02 and both transferred optional resource metadata to optional task/required task partitions for C14. Thus quota/context pressure does not explain away the semantic failures.

Compact C02 took Groq **75.09s** and Nemotron **25.74s**; C14 took Groq **10.84s** and Nemotron **16.13s**. These are observed client wall times, not isolated token-generation benchmarks: local command delays were observed during this session, and the compact calls did not record HTTP 429 retries. Do not attribute Groq's compact 75-second time specifically to quota waiting. More repetitions and an otherwise quiet host are needed for a stable speed ranking. In the current Marina loop, Nemotron had the stronger preliminary delivery reliability; neither provider is qualified for planning correctness.

[Groq supports JSON object and JSON schema modes](https://console.groq.com/docs/openai). [Strict structured outputs cannot currently be combined with native tool use](https://console.groq.com/docs/structured-outputs). JSON enforcement is worth testing for Marina's existing text-envelope loop; it cannot prove task scope, task meaning, arithmetic or completion.
