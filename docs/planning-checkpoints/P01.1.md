# P01.1 — Typed identities and bounded planning contracts

Date: 3 October 2026. Starting commit: `0ee053f84fb46970cd0ab904572d2959b221510a`. User authorized continuation from P00, then expanded the work through P02. This checkpoint covers P01.1 only; the remaining foundations are tracked separately.

## Delivered behavior

`CHAT-01` is now an ordinary passing regression. Tool observations record an entity's kind and ID together. Resource discovery, document reads and visual evidence cannot establish task identity; source prose, arbitrary metadata, echoed filters and missing-ID lists do not establish identities. Current task/goal/routine reads and saved resource associations retain their typed relationships.

Proposal preparation checks referenced IDs against their exact active database tables before inserting a durable proposal. Calendar previews check selected tasks before loading the scheduler. Apply independently revalidates stored payloads and locks referenced rows in its existing transaction. A missing target produces a rejected action, never a substitute task.

Shared contracts define task/goal/resource/work-item references, work items, unknown/known/range effort and unknown/partial/current/stale evidence. Unknown effort is explicitly null; measured zero remains distinct. Current evidence requires a generation. Ordered time/page ranges, duplicate temporary IDs and unsupported action names are checked.

The existing calendar and alternatives widgets now parse responses at runtime. Invalid previews show an accessible error with a 44px reload control. A malformed refresh preserves the previous usable preview. Signed capacity gaps remain valid; unknown effort is never silently converted to zero by these contracts.

## Bounds and compatibility

- Planning/model payloads: at most 256 KiB serialized UTF-8, depth 16, 10,000 visited nodes and 1,000 entries per collection. An iterative conservative byte guard may reject some payloads below the absolute byte maximum. A final serialization check includes JSON escape expansion.
- New planning contexts: 200 typed references, 100 work items and 100 evidence references per item; 30 model actions maximum. Calendar previews retain a maximum 120-day window.
- Legacy action field names remain compatible. No schema migration, model switch, reindex or library scan is required.
- These work-item contracts prepare persistent plans; P01.1 does not claim that plan persistence, calibrated estimates or a new scenario evaluator exists.
